# AI Terminal Operations Assistant

An agentic RAG assistant for container-terminal operations. Users ask natural-language
questions; the system routes each question to a SQL query, document retrieval (RAG), or
both, and returns a grounded answer with sources.

## Important: this is a portfolio project

This project is inspired by the logistics / container-terminal domain but is **not**
affiliated with, built at, or using any data, documents, systems, or architecture from
any employer. All data is synthetic:

- The PostgreSQL container/vessel data is generated by a seed script (see `data/seed/`).
- The SOP documents (`data/documents/`) are original, written for this project.
- No performance numbers, accuracy figures, or usage claims in this repo are invented —
  anything quantitative here was actually measured by the evaluation scripts in
  `scripts/` / `docs/`.

## Local setup (Phase 1)

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env

uvicorn app.main:app --reload
```

Then visit `http://127.0.0.1:8000/health`.

Run tests:

```bash
pytest
```

## Local database (Phase 2)

A formal `docker-compose.yml` arrives in Phase 14. Until then, run Postgres directly:

```bash
docker run --name terminal-assistant-postgres \
  -e POSTGRES_USER=terminal -e POSTGRES_PASSWORD=terminal \
  -e POSTGRES_DB=terminal_assistant \
  -p 5433:5432 -d postgres:16-alpine

docker exec terminal-assistant-postgres \
  psql -U terminal -d terminal_assistant -c "CREATE DATABASE terminal_assistant_test;"
```

Generate synthetic data and load it:

```bash
python scripts/generate_seed_data.py   # writes data/seed/*.csv (deterministic, seed=42)
python scripts/load_seed_data.py       # creates tables and loads them into DATABASE_URL
```
